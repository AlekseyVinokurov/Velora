# Ручная публикация Velora

1. Откройте GitHub → **AlekseyVinokurov/Velora → Actions**.
2. Выберите **Publish Velora Release**.
3. Нажмите **Run workflow**, оставив ветку `main`.
4. Введите `run_id` успешной Android release-сборки. Это число в конце ссылки на её запуск: `…/actions/runs/123456`.
5. Запустите публикацию. Версия, APK и остальные данные определятся автоматически.
6. После успешного завершения откройте **Summary** запуска: там будут ссылки **Release** и **APK**. Прямой APK также появится в разделе **Releases** репозитория.

Публикуйте до следующих изменений приложения в `main`, пока артефакт сборки не истёк. Пересборка, PAT и дополнительные секреты не нужны. Самостоятельная успешная Android-сборка ничего не публикует.

Существующие релизы и теги не заменяются. Полностью загруженный draft от той же сборки и того же коммита публикации можно безопасно продолжить повторным запуском с тем же `run_id`; неизвестный, неполный или изменённый draft остановит публикацию. Не удаляйте и не заменяйте его файлы для обхода проверки.

Если GitHub вернул ошибку, журнал покажет HTTP-код, метод и endpoint без токена. Исправьте указанную причину перед новым ручным запуском.

Для сопровождающих: подпись и Android identity проверяет исходный CI. Публикация проверяет происхождение и успешность этих проверок, digest архива из GitHub API, квитанцию, постоянный certificate pin и SHA-256 фактических байтов APK. Между исходным коммитом APK и коммитом публикации допускаются только файлы механизма публикации, его тестов, этой инструкции и release notes. В metadata сохраняется исходный `sourceCommit`; тег указывает на проверенный коммит публикации. Готовый APK скачивается только на GitHub-hosted runner.
