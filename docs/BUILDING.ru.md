# Сборка Velora

Фактические результаты — в [VELORA_STATUS.md](VELORA_STATUS.md). Сам запуск Gradle или успешный host-тест политики обновления не означают успешную сборку приложения Android.

## Окружение

| Компонент | Основная standalone-сборка |
| --- | --- |
| JDK | Рекомендуется 21; проект поддерживает 17 |
| Gradle / Android Gradle Plugin | Wrapper 8.13 / 8.13.2 |
| SDK / Build Tools | 36 / 36.0.0 |
| NDK / CMake | 26.3.11579264 / 3.22.1 |
| Минимальный API / ABI | API 24; ARM64 и ARMv7 |

Используйте рекурсивный checkout зафиксированных версий субмодулей:

```bash
git clone --recursive https://github.com/AlekseyVinokurov/Velora.git
cd Velora
python3 scripts/setup-android.py
```

Скрипт использует официальный Android-репозиторий Google, устанавливает пакеты в игнорируемый `.local-build/android-sdk` и записывает `sdk.dir` в игнорируемый `local.properties`. При самостоятельном запуске прочитайте запросы лицензий SDK. До распаковки загружается около 1 ГБ; эмулятор и системный образ не устанавливаются. При необходимости задайте JDK через `JAVA_HOME`; чужой абсолютный путь к JDK в Git не хранится.

Для чистого checkout с отсутствующими субмодулями используйте `git submodule update --init --recursive`, без `--remote`. Не перезаписывайте этим чужие изменения. Нативные архивы и сгенерированные wrappers в `TMessagesProj/jni/prebuild` должны соответствовать исходникам.

Унаследованные Huawei/HockeyApp/test-модули сохраняют объявление NDK 27.2.12479018. Это не основной STABLE-вариант выпуска. Python/Chaquopy Gradle plugin в основном APK не объявлен; Python 3 нужен локальным инструментам, а не вместо Android-компиляции.

Для первой локальной настройки выполните `python3 scripts/configure-local-release.py` в своём терминале. Скрипт сохраняет существующий ключ или создаёт постоянный ключ вне Git, закрепляет публичный сертификат и записывает ваши Telegram-параметры и подпись в игнорируемый `private.properties` с правами `0600`. Пароли вводятся без отображения. Сделайте две резервные копии того же ключа; пароли храните отдельно.

## Локальные параметры Telegram

Скопируйте шаблон, только если локального файла еще нет:

```bash
umask 077
test -e private.properties || cp private.properties.example private.properties
```

В локальном редакторе внесите в `private.properties` собственные `TELEGRAM_API_ID` и `TELEGRAM_API_HASH` с [my.telegram.org](https://my.telegram.org). ID — положительное целое, HASH — 32 шестнадцатеричных символа. Проверка формата не подтверждает выдачу пары Telegram. Резервных чужих значений нет. Не вставляйте значения в команды shell, Issues, скриншоты или Git.

Переменные окружения имеют приоритет; прежние Gradle project/local properties поддерживаются. Дополнительные поля шаблона не создают backend-сервисы. При работе с release-секретами не используйте `--debug`, `--info`, build scans и configuration cache.

## DEV APK

```bash
./gradlew --no-daemon :TMessagesProj_AppStandalone:assembleAfatDebug
```

Результат: `TMessagesProj_AppStandalone/build/outputs/apk/afat/debug/app.apk`.

ApplicationId: `io.github.alekseyvinokurov.velora.dev`, название **Velora DEV**, локальный debug-ключ Android. Стабильный updater в DEV отключен. DEV обновляется вручную с тем же локальным debug-ключом; удаление допускается только с пониманием потери его отдельных данных. DEV устанавливается рядом со STABLE.

## STABLE APK

Создайте настоящий постоянный ключ, сохраните резервные копии и закоммитьте публичный отпечаток по [RELEASING.ru.md](RELEASING.ru.md). Перед стабильной сборкой закоммитьте проверенные исходники:

```bash
scripts/build-stable.sh
```

Скрипт интерактивно запрашивает путь к внешнему keystore, alias, пароли и, если локальной конфигурации нет, параметры Telegram. Секреты передаются через окружение краткоживущего процесса, а не аргументы команд; Gradle запускается без постоянного daemon и configuration cache. Не запускайте скрипт с трассировкой и не записывайте сеанс терминала.

После интерактивной локальной настройки выше используйте `scripts/build-stable.sh --local`: параметры берутся из игнорируемой локальной конфигурации без повторного ввода. Проверки чистоты исходников и постоянного сертификата сохраняются.

В среде с примерно 8 ГиБ RAM, разделяемой с IDE, используйте `scripts/build-stable.sh --local --low-memory`. Режим ограничивает heap Gradle до 3 ГиБ, оставляет один Gradle worker, компилирует Kotlin в том же процессе и задаёт CMake/Ninja job pools: две native-компиляции и одна линковка. Сам по себе `--max-workers` не ограничивает Ninja. Меняются только ресурсы сборки; функциональность и постоянная подпись остаются прежними.

Для APK под Pixel 8 добавьте `--arm64-only`: `scripts/build-stable.sh --local --low-memory --arm64-only`. Существующий параметр `ngArm64Only` применяется и к библиотеке, и к standalone-модулю; полученный APK поддерживает только ARM64. Без этого параметра сохраняется сборка ARM64/ARMv7. Пакет, версия и постоянный подписант одинаковы в обоих режимах.

Основная задача — `:TMessagesProj_AppStandalone:assembleAfatStandalone`; результат — `TMessagesProj_AppStandalone/build/outputs/apk/afat/standalone/app.apk`. ApplicationId остается **`io.github.alekseyvinokurov.velora`**. Gradle отклоняет стабильную сборку без закрепленного внешнего RSA-4096 ключа и действительного сертификата с исходным сроком не менее 30 лет. Сертификат должен совпадать с `release/certificate.sha256`.

После проверки реального APK wrapper создает игнорируемый `.local-build/stable-build.json`: хеш APK, версия, сертификат и чистый source commit. Это вход для подготовки релиза. Keystore не копируется. Без реально проверенного APK receipt не создается.

## Идентификаторы, версии и интеграции

`APP_VERSION_NAME` и `APP_VERSION_CODE` в `gradle.properties` — единый фиксированный источник версии. Первая запланированная версия: `0.1.0` / `100000`. Запуск Gradle не увеличивает их, ABI-суффиксы к коду APK не добавляются. Для нового опубликованного выпуска явно измените и закоммитьте оба значения; не заменяйте содержимое уже опубликованного тега.

Namespace и Java-пакеты сохранены. Debug-варианты используют `.dev`; унаследованные regular/test-варианты `.web` не являются основным STABLE-дистрибутивом. Authorities, Android account type и MIME-типы контактов зависят от конечного applicationId, включая `.dev`; Telegram/TON deep links и JNI-имена сохранены. Другой applicationId не переносит приватные данные другого приложения.

Google/Firebase и Huawei JSON должны принадлежать вам и соответствовать пакету/сертификату. В standalone/regular Google-конфигурация необязательна; без своего service JSON не следует рассчитывать на push, OAuth и другие настроенные интеграции. Huawei сохраняет требования своих плагинов. Файлы и API-ключи не должны попадать в Git. Удаленные значки остаются отдельной необязательной настройкой; прежний Telegram-канал обновлений отключен.

Процесс фиксирует исходники/субмодули, версии и инструменты, внешнюю подпись и команды. Побайтовая воспроизводимость APK пока не доказана; сама подготовка процесса не дает оснований ее заявлять.

## Проверки

```bash
python3 tests/release/run.py
python3 scripts/release.py verify TMessagesProj_AppStandalone/build/outputs/apk/afat/standalone/app.apk
```

Первая команда компилирует рабочие классы политики updater и выполняет host-тесты на маленьких временных APK с отдельными случайными тестовыми ключами. Проверяются отказы для неправильных метаданных, подписи и хеша. Это не сборка/установка Velora и не создание постоянного ключа.

Вторая команда проверяет настоящий стабильный APK через SDK `aapt2`/`apksigner`, сравнивает пакет/версию/сертификат с настройками проекта, считает SHA-256 и отклоняет APK со встроенными файлами подписи/приватной конфигурации. Подготовка релиза и тестирование на устройстве — в [RELEASING.ru.md](RELEASING.ru.md).
